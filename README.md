# DC&M 동아리 사이트

DC&M 미니 해커톤 1조 결과물입니다. 동아리 소개와 모집에 더해, 부원이 직접 프로젝트를 올려 사람을 모으고, 참여가 확정되면 개인 캘린더에 모임이 들어가며, 결과와 후기는 커뮤니티로 이어지는 **동아리 운영 허브**입니다.

- 화면: React 18 + Vite (모집 랜딩만 TSX + Tailwind v4, 따로 불러옵니다)
- 데이터·로그인: Supabase (연결 전에는 예시 데이터로 동작)
- 배포: Vercel 또는 GitHub Pages
- 디자인: Figma 시안과 같은 색(#362E2D 갈색, #E3311D 빨강, #AAACA1 회녹색)과 IBM Plex Sans KR

## 메뉴 구조

```
멤버
프로젝트 ▾  ─ 프로젝트 목록 (진행 중 / 모집 중 탭)
           ─ 완료 프로젝트
           ─ 프로젝트 신청 (모집글 쓰기, 화면 오른쪽 아래 버튼으로도 이동)
공지사항
일정
커뮤니티   ─ 프로젝트 후기 · 결과물 · 자유 · 질문 · 건의
내 활동    ─ 개인 캘린더, 참여 중인 활동, 신청 현황, 내가 올린 모집(수락/거절), 내가 쓴 글
지원하기 · 운영진 화면
```

| 커뮤니티 | 분류, 최신/인기 정렬, 검색, 글쓰기(프로젝트 연결), 댓글, 공감, 본인·운영진 삭제 |
| 지원·문의 | 입력값 검사, 개인정보 동의(목적·항목·기간·거부권), 제출 완료 화면 |
| 공통 | 반응형(390px), 다크 모드, 통합 검색, 운영진 화면(지원서·공지·일정·멤버·프로젝트·게시글·모집 설정) |

## 모집 랜딩 페이지 켜기/끄기

모집 기간에는 사이트 주소(`/`)에 처음 오는 **로그인하지 않은 방문자**에게 메인 대신 모집 랜딩(`src/landing`)을 보여 줄 수 있습니다. **로그인한 부원**에게는 언제나 평소 메인(Home)이 보이고, 메인 사이트 열람은 지금처럼 공개입니다.

운영진 화면 > **사이트 설정**에서 정합니다.

| 설정 | 설명 |
| --- | --- |
| 지금 지원을 받습니다 | 켜져 있어야 랜딩을 켤 수 있습니다 |
| 모집 시작일 · 마감일 | 오늘(한국 시간)이 시작일~마감일 안일 때만 켤 수 있습니다. 둘 다 있어야 하고 마감일 당일까지 포함합니다 |
| 모집 랜딩 페이지 켜기 | 조건이 맞지 않으면 비활성(이미 켜져 있다면 끄기만 가능)이고 이유가 안내됩니다 |

- 방문자에게 랜딩이 보이는 조건은 `지금 지원을 받습니다` **그리고** `모집 기간 안` **그리고** `랜딩 켜기`입니다 (`src/lib/landing.js`). 기간이 지나면 스위치가 켜져 있어도 자동으로 메인이 보입니다. 저장된 값은 그대로 두므로 다음 모집 때 날짜만 바꾸면 됩니다.
- 설정을 불러오지 못하면 랜딩 대신 메인을 보여 줍니다.
- **`/#/recruit`**: 랜딩이 켜져 있으면 누구나, 꺼져 있어도 **운영진은 미리 보기**로 볼 수 있습니다. 그 외에는 `/`로 돌아갑니다. 운영진 화면의 `랜딩 미리 보기` 링크가 여기로 이어집니다.
- 랜딩의 서류 접수 일정(배지 D-day, 카운트다운, 일정 첫 단계, 터미널 `recruit`·`schedule`)은 `모집 시작일 00:00 ~ 마감일 23:59:59`(KST)로 맞춰집니다. 서류 발표·면접 같은 나머지 단계와 기수 표기는 `src/landing/data/site.ts`에 있습니다.
- 랜딩의 링크: 멤버 → `/members`, 활동 → `/projects/done`, 지원하기 → `/apply`, 문의하기 → `/apply?tab=inquiry`, 부원 로그인 → `/login`. 소개·모집 안내 같은 섹션 이동은 주소를 바꾸지 않고 스크롤만 합니다 (HashRouter에서는 `#about`이 경로로 읽히기 때문).

**이미 만든 Supabase DB**에는 새 칸을 한 번 추가해야 합니다. SQL Editor에서 실행하세요. (새로 만드는 DB는 `schema.sql`에 이미 들어 있습니다.)

```sql
alter table settings add column if not exists recruit_start date;
alter table settings add column if not exists landing_enabled boolean not null default false;
alter table settings add column if not exists recruit_details jsonb;
```

### 모집 내용 고치기 (운영진 화면 > 사이트 설정)

사이트 설정은 "모집 기본 / 모집 일정 / 지원 자격 / 자주 묻는 질문 / 사이트 기본"으로 나뉘어 있고, 저장하면 모집 랜딩에 바로 반영됩니다. 저장 전에 입력을 검사합니다 (기수는 1 이상의 정수, 단계 이름 필수, 뒤 단계는 앞 단계보다 늦게, 끝은 시작보다 뒤, 질문·답 필수). 오류는 해당 칸 옆에 표시됩니다.

- **기수**는 랜딩의 모든 "N기" 표기(히어로, 카운트다운, 터미널, 지원 버튼, 숫자로 보는 DC&M의 기수 등)에 쓰입니다. 기수를 바꾸면 일정·자격·FAQ 문구 안의 "N기"도 화면에서 함께 바뀌니, 저장 전에 확인하세요.
- **첫 단계(서류 접수)** 의 날짜는 `recruit_start`·`recruit_deadline`이 곧 그 값입니다. 마감 시각(기본 23:59)만 따로 정하고, 랜딩 켜짐 판정은 날짜만 봅니다.
- 비어 있는 항목(기존 DB 포함)은 `src/data/recruitDefaults.js`의 기본값을 씁니다.
- 메인 `지원하기` 페이지의 "지원 후 진행 순서" 문구는 고정 문구라 이 설정과 연결하지 않았습니다.

`settings.recruit_details`(jsonb) 형식 예시 (날짜·시각은 KST):

```json
{
  "generation": 8,
  "applyEndTime": "23:59",
  "steps": [
    { "title": "서류 접수", "description": "온라인 지원서로 ...", "start": "2026-11-03T00:00:00+09:00", "end": "2026-11-23T23:59:59+09:00" },
    { "title": "서류 발표", "description": "합격 여부와 ...", "start": "2026-11-26T18:00:00+09:00" },
    { "title": "대면 면접", "description": "20분 내외의 ...", "start": "2026-11-28T10:00:00+09:00", "end": "2026-11-29T18:00:00+09:00" }
  ],
  "qualifications": ["개발에 관심 있는 재학생이라면 전공·학년 무관"],
  "faqs": [{ "q": "비전공자도 지원할 수 있나요?", "a": "물론이에요. ..." }]
}
```

### 첫 방문 인트로

`/`에 처음 들어온 사람에게 한 번만 인트로(`src/intro`)를 보여 주고, 랜딩일 때도 평소 메인일 때도 같습니다. 본 기록은 브라우저 `localStorage`(`dcm-intro-seen`)에 남습니다.

- 주소를 **`/?intro#/`** 로 열면 본 기록과 상관없이 다시 재생합니다 (발표용). 사이트 안에서 다른 화면에 갔다가 돌아올 때는 다시 틀지 않습니다.
- 브라우저의 '동작 줄이기' 설정이 켜져 있으면 재생하지 않습니다.
- 첫 화면이 인트로 전에 보였다 사라지지 않도록, 화면을 가리는 스크립트와 CSS가 `index.html`의 `<head>`에 인라인으로 들어 있습니다 (홈 경로일 때만 동작). 재생 조건을 바꾸면 `index.html`과 `src/intro/Intro.tsx`를 같이 고치세요.

### 랜딩 코드를 고칠 때

- 랜딩(`src/landing`)은 Next.js로 만든 모집 페이지를 옮겨 온 TSX입니다. `@/`가 `src/landing`을, `@intro/`가 `src/intro`를 가리킵니다. `npm run typecheck`로 타입을 검사합니다.
- 랜딩은 `React.lazy`로 따로 불러오므로 꺼져 있는 동안 motion·lenis·Tailwind CSS가 메인 번들에 실리지 않습니다.
- CSS 규칙: `src/index.css`가 레이어 순서(`site, theme, base, components, utilities`)를 선언하고 기존 `styles.css`를 가장 낮은 `site` 레이어에 넣습니다. Tailwind는 랜딩 폴더만 스캔하고, preflight는 전역이 아니라 `.landing` 안에만 적용됩니다. **메인 화면 클래스 이름이 Tailwind 유틸리티 이름(`block`, `grid`, `hidden` 등)과 같으면** 랜딩을 한 번 연 뒤 메인 화면이 바뀔 수 있으니 다른 이름을 쓰세요. (그래서 전체 폭 버튼은 `.btn.wide`입니다.)

## 바로 실행 (예시 데이터)

```bash
npm install
npm run dev
```

`http://localhost:5173`을 엽니다. Supabase 없이도 모든 화면이 동작하고, 바꾼 내용은 그 브라우저에만 저장됩니다.

- 헤더의 **로그인**에서 예시 멤버 한 명을 고르면 그 사람으로 들어갑니다.
- **이현성(부원)**: 참여 신청, 모집글 쓰기, 내가 올린 모집의 신청자 수락/거절을 볼 수 있습니다.
- **문선우(회장)**: 운영진 화면과 '동아리 개설로 올리기'까지 쓸 수 있습니다.
- 푸터의 **예시 데이터로 되돌리기**로 처음 상태로 돌아갑니다.

## Supabase 연결 (실제 운영)

1. [supabase.com](https://supabase.com)에서 동아리 **공용 계정**으로 새 프로젝트를 만듭니다.
2. SQL Editor에서 `supabase/schema.sql`을 실행합니다. 멤버·공지·일정 예시가 필요하면 `supabase/seed.sql`도 실행합니다.
3. 운영진 이메일을 등록합니다: `insert into admins (email) values ('운영진이메일@example.com');`
4. Authentication > URL Configuration의 Site URL과 Redirect URLs에 배포 주소를 넣습니다.
5. Project Settings > API의 URL과 anon key를 `.env`에 넣습니다.
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```
6. 부원이 이메일로 처음 로그인하면 `profiles`에 승인 전 상태로 등록됩니다. 운영진이 확인한 뒤 승인합니다.
   ```sql
   update profiles set approved = true, name = '이현성', part = '웹' where email = '부원이메일@example.com';
   ```

접근 규칙(RLS) 요약

- 공지·일정·멤버·모집 설정: 누구나 읽기, 운영진만 쓰기
- 프로젝트·문의·게시글·댓글: 누구나 읽기, **승인된 부원**이 자기 이름으로만 쓰기, 본인·운영진이 수정·삭제
- 참여 신청: 본인·프로젝트 작성자·운영진만 보기, 수락/거절은 작성자·운영진
- 개인 프로필(이메일): 본인과 운영진만 보기
- 지원·문의: 누구나 제출만, 열람·삭제는 운영진
- anon key는 공개돼도 되는 키입니다. **service_role 키는 절대 코드나 저장소에 넣지 마세요.**

## 배포

**Vercel**: 저장소 Import → Vite 자동 인식 → Environment Variables에 위 두 값 → Deploy. 무료 요금제는 비상업·개인 용도로 제한되니, 동아리 계정으로 쓰기 애매하면 GitHub Pages를 쓰세요.

**GitHub Pages**: `npm run build` 후 `dist` 폴더를 올립니다. 해시 주소(`#/projects`)를 써서 하위 경로에서도 새로고침 404가 나지 않습니다.

## 운영·인수인계 체크리스트

- [ ] GitHub 저장소, Supabase, Vercel을 개인 계정이 아니라 동아리 공용 계정에 둔다
- [ ] 기수가 바뀌면 `admins`에서 이전 운영진을 지우고 새 운영진을 넣는다
- [ ] 모집을 시작하기 전에 운영진 화면 > 사이트 설정에서 모집 시작일·마감일을 정하고 랜딩을 켠다
- [ ] 새 학기에 들어온 부원의 `profiles.approved`를 켜 준다
- [ ] 모집이 끝나면 30일 안에 운영진 화면에서 **지원·문의 전부 파기**를 누른다
- [ ] Supabase 무료 프로젝트는 1주일 동안 요청이 없으면 일시정지된다. 방학 전에 담당자를 정한다
- [ ] 끝난 프로젝트는 작성자가 **완료 처리**하도록 안내한다 (완료 프로젝트 화면으로 옮겨짐)

## 폴더 구조

```
src/
  lib/api.js        데이터 계층 (Supabase ↔ 예시 데이터 전환, 개인 로그인)
  lib/projects.js   프로젝트 상태·마감·정기 모임 계산
  lib/recruitDetails.js  모집 내용(recruit_details) 기본값 합치기·폼 변환·입력 검사
  lib/landing.js    모집 랜딩 켜짐 판정 (모집 기간, 지원 받는 중, 랜딩 켜기)
  lib/validate.js   지원·문의 입력값 검사
  data/seed.js      예시 데이터
  components/       헤더(프로젝트 메뉴), 이번 주 시간표, 카드·캘린더 등 공통 UI
  pages/            메인, 멤버, 프로젝트, 공지, 일정, 커뮤니티, 내 활동, 지원, 검색, 운영진
  landing/          모집 랜딩 (TSX + Tailwind v4, lazy로 따로 불러옴)
  intro/            첫 방문 인트로 (홈 `/`에서만, 랜딩·메인 공통)
supabase/
  schema.sql        표와 접근 규칙
  seed.sql          멤버·공지·일정 예시 (npm run seed-sql로 다시 만들 수 있음)
```

멤버 이름, 개인 프로젝트, 게시글은 화면 확인용 예시입니다. 실제 운영 전에 바꿔 주세요.
